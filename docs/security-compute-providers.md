## 1. 威胁模型

### 1.1 信任边界

```
┌─ 不信任域 ──────────────────────────────────────────┐
│  算力客户端（第三方，可能恶意）                         │
│  · 伪造计算结果                                       │
│  · Sybil 攻击（多身份重复领取）                        │
│  · 串通（多客户端对同一任务重复提交）                    │
│  · 重放（截获合法结果重新提交）                         │
└──────────────────────┬───────────────────────────────┘
                       │ 控制通道（HTTP/WS）+ 数据通道（DCNet）
                       ▼
┌─ 信任域（infer 控制面）────────────────────────────────┐
│  · 客户端注册鉴权（/auth 机器凭证）                     │
│  · 任务完成验证（结果校验）                             │
│  · 防滥用（限额、速率、冻结、撤回）                      │
└──────────────────────┬─────────────────────────────────┘
                       │ 平台内部调用（B 端凭证 + productId 白名单）
                       ▼
┌─ 信任域（uc 账本）─────────────────────────────────────┐
│  · 纯记账（不判断"该不该发"）                           │
│  · 订单记录（存入凭证）                                 │
│  · 账本事件（postLedgerEvent）                          │
└─────────────────────────────────────────────────────────┘
```

### 1.2 攻击向量与防线

| 攻击 | 防线 | 层级 |
|---|---|---|
| 伪造计算结果 | 任务完成验证（§2） | infer 控制面 |
| Sybil 多身份 | 客户端注册鉴权 + 注册限额 / 声誉门槛（§3；2026-09-07 修订：不收硬件指纹） | infer 控制面 |
| 重放攻击 | requestId 幂等 + 时间戳窗口（§4） | infer + uc |
| 串通重复提交 | 调度器绑定（MVP 整图单客户端）+ 结果去重（§5） | infer 控制面 |
| 凭证泄露 | productId 白名单 + 单笔上限 + 熔断（§6） | uc 端点 |
| 内部台账篡改 | DB 事务 + 审计日志 + 对账（§7） | infer 控制面 |
| **控制通道窃听**（REST/WS 部署面明文；张量面已由预签名 URL 的 HTTPS 承担——2026-09-07 数据面修正，原「数据通道无 TLS」风险大体消解） | 部署侧缓解：前置 TLS 代理终止；见 DESIGN §11 | 控制通道（server ↔ client） |

## 2. 任务完成验证

### 2.1 验证策略（按成本递增）

| 策略 | 适用场景 | 成本 | 安全等级 |
|---|---|---|---|
| **结果格式校验** | 所有任务 | 低 | 基础（防明显垃圾） |
| **数值范围检查** | 推理输出有预期范围 | 低 | 基础（防异常值） |
| **冗余执行** | 高价值任务 | 高（N 倍算力） | 强（多数一致才确认） |
| **抽样审计** | 常规任务 | 中（抽样比例） | 中（事后检出） |
| **中间结果哈希** | DCNet 可承载 | 低 | 中（防篡改，不防伪造） |

### 2.2 MVP 策略（P1）

- **结果格式校验**：输出张量形状、数据类型与图 Schema 匹配
- **数值范围检查**：推理输出在预期范围内（如概率 ∈ [0,1]）
- **单客户端绑定**：MVP 整图单客户端，无串通面

### 2.3 增强策略（P2+）

- **冗余执行**：高价值任务派发 N 个节点，多数一致才确认
- **抽样审计**：随机抽取 X% 任务用可信节点复算，不一致则冻结
- **声誉累积**：新客户端初始验证严格，随正确完成次数放宽

### 2.4 难度系数计费信任（2026-09-07 裁决 V13）

难度钩子为**模型开发者**定义的内容级函数（输入张量 → 难度系数），client 执行面计算并随完成上报——属不信任域自报值。**裁决：不建抽样审计**，信任机制为：

- **市场竞争**：模型报价（单价 × 难度）对消费者可见，异常定价被市场淘汰
- **直营精算**：平台直营模型自行定价，有精算兜底

残留风险（记录不处置）：提供者虚报难度系数 → 由价格可见性与直营定价锚定；后续若出现系统性偏差，再评估引入上限钳制（P3+）。关联 [server/DESIGN.md](../server/DESIGN.md) D12。

## 3. 客户端注册鉴权

### 3.1 注册流程

```
客户端上线 → 提供机器凭证（/auth 签发）→ infer 验证凭证 → 注册到 /registry
                                    ↓
                          绑定 accountId（平台账户）
                          初始声誉 = 0
```

### 3.2 Sybil 防御（2026-09-07 修订：不收硬件指纹）

- **设备指纹不收集**（capability 访谈裁决：端点语义不描述终端配置）；Sybil 防御改**账号维度**
- **注册限额**：单账号 / 单 IP 每日注册上限
- **声誉门槛**：新客户端需完成 N 个低价值任务后才可接高价值任务
- **人工审核**（可选）：高价值任务需客户端通过人工审核

### 3.3 凭证管理

- 客户端凭证经 /auth 签发（client_credentials 模式）
- infer 验证凭证 active + productId 匹配
- 凭证泄露时可吊销（/auth 侧操作）

## 4. 重放攻击防御

### 4.1 幂等键设计

- **任务级**：`requestId = hash(client_id, task_id)`，同一客户端同一任务只记一次
- **存入级**：`requestId = batch_id`（infer 生成 UUID），同一批次只存入一次

### 4.2 时间戳窗口

- 任务结果提交有时间窗口（如任务派发后 30 分钟内）
- 超窗口的提交拒绝（防截获旧结果重放）

### 4.3  nonce（可选）

- 高安全场景：任务派发时附带 nonce，结果提交时回传
- 防止截获结果后修改时间戳重放

## 5. 串通防御

### 5.1 调度约束

- **MVP**：整图绑定单客户端，无串通面
- **P2 分区**：有互斥关系的节点必须绑定同一客户端（DESIGN §11）
- **环/反馈回路**：整体绑定同一客户端（跨网往返塌语义）

### 5.2 结果去重

- 同一任务多客户端提交时（冗余执行），结果需多数一致
- 完全相同的结果（字节级）可能为串通，需额外验证

## 6. uc 端点兜底

### 6.1 productId 白名单

- `INTERNAL_DEPOSIT_PRODUCTS` 环境变量配置允许调用 deposit 的 productId
- 非白名单产品调用 → 403

### 6.2 单笔上限

- deposit 端点可配置单笔存入上限（如 10000 积分）
- 超限 → `{ ok: false, reason: "DEPOSIT_LIMIT_EXCEEDED" }`

### 6.3 全局熔断

- 管理端 API 可按 productId 一键熔断 deposit（紧急止血）
- 熔断期间所有 deposit 请求 → 503

## 7. 审计与对账

### 7.1 infer 侧审计日志

- 每次任务完成验证：记录 client_id、task_id、验证结果、验证策略
- 每次存入：记录 batch_id、account_id、total_points、task_count、uc_order_no
- 异常事件：冻结、撤回、限额触发

### 7.2 对账

- **infer 内部**：`infer_reward_ledger` 汇总 vs `infer_deposit_batch` 总额
- **infer ↔ uc**：`infer_deposit_batch.uc_order_no` vs uc `payment_order` 记录
- **uc 内部**：`payment_order`（deposit 渠道）vs `point_ledger_event`（deposit 类型）

### 7.3 撤回机制

- 发现欺诈后，infer 可冻结客户端内部台账（status=frozen）
- 已存入 uc 的积分需走 uc 侧 adjust 流程（人工介入）
- 未来可支持：infer 发起"撤回存入"（负向 deposit），需 uc 侧配合

## 8. 经济博弈（P3+ 可选）

### 8.1 质押/保证金

- 客户端注册时锁定一笔积分（或法币保证金）
- 发现欺诈则 slash（扣除质押）
- 需 uc 侧支持"冻结/扣除质押"操作

### 8.2 延迟存入

- 存入不立即到账，设 T+N 冷却期（如 24h）
- 冷却期内可撤回（发现欺诈时）
- 需 uc 侧支持"待确认"状态（eventType="deposit_pending" → "deposit_confirmed"）

### 8.3 声誉系统

- 客户端声誉分（正确完成次数、任务难度、在线时长）
- 高声誉：验证宽松、限额高、优先调度
- 低声誉：验证严格、限额低、需质押
